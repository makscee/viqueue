# viqueue v0.5.1 prerelease

> Prerelease for controlled private evaluation; not production-ready.

v0.5.1 fixes local install and rollback release-pointer rotation on BSD/macOS while preserving the existing behavior on GNU/Linux. The prior shell implementation used GNU `mv -Tf`; the BSD `mv` shipped by macOS rejects `-T`, and omitting that option can follow an existing destination symlink instead of replacing the pointer itself. This reproduced failure prevented the packaged local scripts from reliably switching `current` and `previous` on those systems.

## Fix

The install and rollback scripts now use Node's `renameSync` to replace each prepared temporary symlink. The rename stays within the same pointer directory, atomically replaces the directory entry, and avoids platform-specific `mv` flags and destination-symlink-following behavior.

## Compatibility and security

This is a compatible patch: CLI, HTTP, storage, archive, authentication, claim-fencing, and rollback contracts are unchanged. Atomic pointer replacement retains the fail-closed local release transition and avoids an intermediate missing-pointer state. Using the project's required Node.js runtime instead of divergent system `mv` implementations reduces cross-platform ambiguity; it does not broaden filesystem permissions or trust boundaries.

## Validation

The focused packaged-script test installs two synthetic releases, verifies `current` and `previous`, rolls back, verifies both pointers again, and checks that temporary pointer paths are removed. The release candidate is also expected to pass the full unit/integration suite, build, tracked-source and history secret scan, full local end-to-end suite, and whitespace-error check.

This candidate does not publish, deploy, install into a user environment, activate a gateway, make a live request, or claim production or live-environment validation. Any tag, package publication, deployment, installation, or externally verified live operation remains a separate authorized action.
