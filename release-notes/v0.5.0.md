# viqueue v0.5.0 prerelease

> Prerelease for controlled private evaluation; not production-ready.

v0.5.0 makes the supported worker lifecycle CLI-first. Workers can redeem one-time pairing codes, open and close sessions, claim work, record fenced progress, list and ask questions, release a blocked claim to Waiting, reclaim after a coordinator answer reopens the ticket, and complete directly with outcome and evidence provenance.

## Compatibility and security

Direct completion is atomic and idempotent. The legacy submit/accept path remains compatible and optional rather than becoming a prerequisite for direct completion. Existing worker mutation receipt tables are migrated additively so exact fenced completion retries retain their receipts. Claim and session fencing, one-time pairing behavior, private-environment trust boundaries, and the v0.4.1 phone-gateway upstream restrictions remain in force.

## Release archive

The deterministic local archive now stages every built `dist/bin` and `dist/src` output. This includes every `package.json` command target together with the server and phone-gateway dependencies. The archive name is derived from the package version and its SHA-256 checksum must verify before installation.

## Validation expectations

A release candidate is expected to pass the unit/integration test suite, build, tracked-source and history secret scan, full local end-to-end suite, two-build deterministic archive hash comparison, checksum verification, and archive-content checks for every declared command plus `src/server.js` and `src/phone-gateway.js`.

This candidate does not publish, deploy, activate a gateway, make a live request, or claim production or live-environment validation. Any production release, deployment, ingress, credentials, or externally verified live operation remains a separate authorized action.
